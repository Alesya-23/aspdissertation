# Стек и решения

Документ фиксирует, из чего собрано решение, какие источники данных
используются и почему выбраны именно эти компоненты. Версии — в
`requirements-rag.txt`, результаты экспериментов — в `data/*.json`.

Статус: рабочая версия от **12.11.2026** (УК РФ + ППВС, гибридный поиск,
локальные GGUF-модели).

## 0. Что изменилось в этой версии

- В корпус добавлены **постановления Пленума Верховного Суда РФ** (ППВС):
  90 постановлений, 2 475 пунктов, 1 651 чанк.
- Появился отдельный чанкер ППВС (`PlenumChunker`) и команда
  `python -m rag.cli ppvs`.
- Индекс стал общим: 842 чанка УК + 1 651 чанк ППВС = **2 493 чанка**.
- В поиск добавлена **балансировка актов**: на вопрос о наказании/составе
  подмешивается норма УК, на вопрос о разъяснениях — хотя бы одно ППВС.
- Добавлены оценки `eval-ppvs` (17 вопросов) и `bench` (сравнение моделей).
- Зафиксированы источники данных и решение по официальному доступу (раздел 2).

## 1. Общая схема

```
УК РФ (522 статьи)                     ППВС (90 постановлений, 2 475 пунктов)
   |                                        |
   v                                        v
corpus.py  ── постатейный JSONL        ppvs.py  ── JSONL с пунктами и реквизитами
   |                                        |
   v                                        v
chunking.py (StructureChunker)         chunking.py (PlenumChunker)
   └──────────────┬─────────────────────────┘
                  v
          embeddings.py  e5-base, 768d, 512 токенов
                  v
          store.py       FAISS IndexFlatIP + BM25
                  v
          retriever.py   RRF + подсказки «ст. N / ч. N» + балансировка актов
                  v
          generate.py    llama.cpp + YandexGPT-5-Lite-8B
                  v
          cli.py         corpus / ppvs / index / ask / search / eval / eval-ppvs / bench / stats
```

## 2. Источники данных и официальный доступ

### 2.1. УК РФ

| Параметр | Значение |
|---|---|
| Источник | `ukodeksrf.ru`, постатейные страницы |
| Что парсится | заголовок статьи, части, подпункты, примечания; комментарии и судебная практика отбрасываются |
| Объём | 522 статьи, 1 689 элементов, 13 статей утратили силу |
| Редакция | снимок 2025 г. (сайт указывает «на 2025 год») |
| Формат | `data/raw/uk_rf.jsonl` + кэш HTML в `data/raw/html/` |

Парсер (`rag/corpus.py`) вырезает всё после заголовка «Комментарий…»,
поэтому в корпус не попадают постатейные комментарии и судебная практика.
Ограничение: источник неофициальный; для юридически значимых задач нужна
сверка с официальной редакцией на дату.

### 2.2. ППВС

| Параметр | Значение |
|---|---|
| Источник | датасет `Alexey5676/russian-supreme-court-plenum-acts` (Hugging Face, лицензия CC0) |
| Первоисточник | официальный раздел документов Пленума на `vsrf.ru` |
| Покрытие датасета | 1 503 постановления 1961–2026 + 1 повестка заседания |
| Отбор в корпус | 90 постановлений по уголовным делам, принятых после 01.01.1997 |
| Объём | 2 475 пунктов, 1 651 чанк |
| Формат | `data/raw/ppvs.jsonl`; исходный датасет — `data/raw/plenum_resolutions.jsonl` |
| Ссылка на оригинал | в каждом чанке хранится `source_url` на vsrf.ru |

Логика отбора (`rag/ppvs.py`):

- только `doc_type = resolution`;
- дата ≥ 1997-01-01 (действующий УК РФ);
- в заголовке/вводной части упоминается Уголовный кодекс или УК РФ;
- исключаются акты «О внесении изменений», «Об изменении и дополнении»,
  «О признании утратившим силу» — они не содержат самостоятельных разъяснений;
- исключаются постановления, помеченные как утратившие силу.

Текст из PDF чистится: колонтитулы, номера страниц, переносы слов,
подписи Председателя/Секретаря. Артефакты PDF-извлечения полностью не
устраняются (см. раздел 7).

### 2.3. Официальный доступ: что есть и что нужно

| Источник | Статус | Годится для RAG? | Комментарий |
|---|---|---|---|
| `vsrf.ru` (раздел документов Пленума) | официальный | да, но парсинг неудобен | сайт на Next.js: контент подгружается динамически, прямой парсинг требует разбора API/JS |
| `pravo.gov.ru` | официальный портал опубликования НПА | ограниченно | доступен по HTTP, но публикует законы по отдельности; консолидированной редакции УК «одним файлом» нет |
| КонсультантПлюс / Гарант | коммерческие СПС | да, при наличии доступа | требуют подписки; автоматический экспорт ограничен лицензией |
| `ukodeksrf.ru` | неофициальный | да | удобная постатейная вёрстка, но редакция не гарантирована |
| HF-датасет ППВС | открытый (CC0) | да | снимок официального раздела vsrf.ru, у каждого документа есть `source_url` |

**Принятое решение:** работаем на снимке `ukodeksrf.ru` + CC0-датасете ППВС.
Для диссертации фиксируем дату снимка и выборочно сверяем тексты с vsrf.ru
по `source_url`. Если появится институциональный доступ к КонсультантПлюс
или Гаранту, меняется только загрузчик в `rag/corpus.py` / `rag/ppvs.py` —
чанкинг, индекс и поиск остаются прежними.

Что нужно для «официального» варианта:

1. либо подписка на СПС с правом выгрузки,
2. либо официальный экспорт/выгрузка с `pravo.gov.ru` (для законов),
3. либо ручная сверка снимка и фиксация редакции на дату (минимальный вариант).

## 3. Выбор компонентов

### Векторное хранилище

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| FAISS (IndexFlatIP) | точный поиск, один файл, нет сервера, миллисекунды на 3–5 тыс. чанков | нет фильтров и метаданных «из коробки» | **выбран**: метаданные лежат рядом в JSONL |
| Chroma | метаданные, фильтры, простой API | тяжёлые зависимости, версионные конфликты, телеметрия | отклонён |
| Qdrant | продовый сервер, фильтры, масштаб | отдельный процесс, Docker | избыточен для монографии/эксперимента |
| pgvector | знакомый SQL | нужен PostgreSQL | избыточен |
| numpy + SQLite | ноль зависимостей | ручной код, нет ANN | резервный вариант при <10 тыс. чанков |

Для 2,5 тыс. чанков FAISS Flat — точный косинусный поиск за единицы
миллисекунд; ANN-индексы (HNSW/IVF) здесь только ухудшат recall. При росте
корпуса до сотен тысяч чанков (УПК, УИК, КоАП, практика) менять нужно только
`store.py`.

### Эмбеддер

| Модель | Размер | Русский | Комментарий |
|---|---|---|---|
| `intfloat/multilingual-e5-base` | 278M, 768d | хороший | **по умолчанию**: баланс качества/скорости, 512 токенов |
| `intfloat/multilingual-e5-large` | 560M, 1024d | лучше | +качество, ~2x медленнее, 2.2 ГБ |
| `deepvk/USER-bge-m3` | 359M, 1024d | сильный на ru | лучший кандидат для сравнения |
| `cointegrated/rubert-tiny2` | 29M, 312d | слабее | только для отладки на CPU |

Юридический текст — длинные нормативные формулировки с редкими терминами;
для них важнее не «понимание», а точное лексическое совпадение, поэтому
чистый dense-поиск дополнен BM25. Для e5 обязательны префиксы
`query:` / `passage:` — они добавляются в `rag/embeddings.py`.

### LLM

Локальные GGUF из корня проекта, через `llama.cpp` (как в `init.py`):

| Файл | Размер | Роль |
|---|---|---|
| `YandexGPT-5-Lite-8B-instruct-Q4_K_M.gguf` | 4.9 ГБ | **по умолчанию**: instruct, русский |
| `saiga_yandexgpt_8b-q4_k_m.gguf` | 4.9 ГБ | альтернатива, влезает целиком |

фрагменты, если промпт не влезает.

## 4. Чанкинг

### 4.1. УК РФ

Ключевое отличие нормы от обычного текста — **адресуемость**: ответ должен
ссылаться на «ст. 158 ч. 2 УК РФ», а не на «фрагмент №37». Поэтому:

1. **Атом — часть статьи**, а не 512 токенов. Подпункты «а)…г)» не отделяются
   от родительской части: «а) двух или более лиц» без «2. Убийство:» — мусор.
2. **Заголовок-контекст** дублируется в каждом чанке:
   `УК РФ. Особенная часть. Раздел VIII. Глава 21. Статья 158. Кража. Часть 2.`
   Это 30–50 токенов накладных расходов, но именно они спасают короткие
   части и дают корректную цитату.
3. **Границы статьи не пересекаются** — иначе в один чанк попадут нормы из
   разных глав, и цитата станет неверной.
4. **Примечания — отдельные чанки**: определения («значительный ущерб»,
   «крупный размер») относятся ко всей статье и ищутся отдельными запросами.
5. **Перекрытие** — только там, где оно нужно:
   - 1 часть на стыке соседних чанков одной статьи (по умолчанию);
   - 15% предложений, если одна часть длиннее лимита и режется;
   - между статьями перекрытия нет — это создаёт ложные цитаты.
6. **Small-to-big**: в индекс идёт точная часть, а в LLM по `--expand article`
   подаётся весь текст статьи (обрезанный по бюджету).

Лимит — 480 токенов при лимите e5 в 512: заголовок съедает 30–50.
Baseline `fixed` (окно 384 токена, overlap 15%) реализован специально, чтобы
проверить структурный чанкинг на размеченных вопросах, а не поверить на слово.

### 4.2. ППВС

Постановления Пленума — не статьи, а пункты, поэтому для них отдельный
чанкер (`PlenumChunker`):

- атом — **пункт постановления** (п. 15, 15.1 и т.д.);
- заголовок содержит реквизиты: `Постановление Пленума ВС РФ от 27.01.1999
  № 1 «О судебной практике по делам об убийстве (ст. 105 УК РФ)». Пункт 15`;
- границы документа не пересекаются, перекрытие — 1 пункт;
- преамбула (если она содержательная) становится отдельным элементом;
- пункты «14, 15. Исключены…» не создают отдельных чанков, а остаются
  в тексте предыдущего пункта (это неизбежное следствие PDF-вёрстки);
- в корпус не попадают акты «О внесении изменений», утратившие силу
  постановления и постановления до 1997 г.

Заголовок ППВС-чанка — это и есть citation: «п. 24 ППВС от 27.12.2002 № 29
„О судебной практике по делам о краже, грабеже и разбое“».

### 4.3. Почему перекрытие именно такое

Перекрытие 1 часть/пункт — компромисс: соседние части часто связаны
(«те же деяния…», «деяния, предусмотренные частью первой…»), но полное
дублирование увеличивает индекс и зашумляет top-k. Внутри длинной части
перекрытие 15% нужно только потому, что часть физически не влезает в 480
токенов; между нормами перекрытия нет.

## 5. Поиск и генерация

- **Гибрид:** dense (FAISS, косинус) + BM25 (Snowball-стеммер для русского),
  объединение через RRF: `k=2`, вес dense `1.0`, вес BM25 `0.8`.
- **Подсказки из запроса:** номера статей («ст. 158») и частей («ч. 3»)
  извлекаются регулярками; для УК они дают буст, а при явном номере —
  жёсткий фильтр по статье. Если в запросе есть «Пленум/постановление/
  разъяснение», фильтр по статье не применяется, а ППВС получает буст.
- **Балансировка актов:** если вопрос про наказание/состав/ответственность,
  а в top-k нет УК — добавляется лучший чанк УК; если вопрос про разъяснения,
  а ППВС нет — добавляется лучший чанк ППВС. Это исправляет перекос, когда
  заголовок ППВС («…о краже, грабеже и разбое») перетягивает запрос
  «какое наказание за кражу».
- **Отсечение шума:** результаты ниже `0.6 × лучший_score` отбрасываются;
  не более 2 чанков на статью/документ.
- **Контекст:** 4–6 фрагментов, для УК — раскрытие до полной статьи
  (`--expand article`), для ППВС — сам пункт.
- **Ответ:** системный промпт требует ссылки `[S1]…[Sn]`, номер статьи/части
  и запрещает ссылаться на нормы вне контекста. Дополнительно
  `_check_articles` предупреждает, если модель упомянула статью, которой
  не было ни в источниках, ни в тексте найденных фрагментов.

## 6. Эксперименты и метрики

### 6.1. Стратегии чанкинга УК РФ

`python -m rag.cli eval`, 62 вопроса (`eval/questions.jsonl`).

| стратегия | чанков | p50 | R@1 | R@5 | MRR | part@5 |
|---|---|---|---|---|---|---|
| structure (overlap 1) | 842 | 296 | 0.903 | 0.984 | 0.940 | 1.00 |
| structure-nooverlap | 842 | 275 | 0.887 | 0.968 | 0.923 | 0.82 |
| fixed (окно 384) | 807 | 361 | 0.903 | 1.000 | 0.949 | 0.00 |

Выводы:

- на уровне статьи обе стратегии близки к потолку (R@5 ≈ 1.0), разница
  в 1–2 вопроса — шум; наивное окно даже чуть выше по MRR, потому что его
  чанк покрывает почти всю статью;
- на уровне части структурный чанкинг выигрывает вчистую: 100% против 0% —
  у оконных чанков просто нет метаданных о части;
- перекрытие в 1 часть поднимает точность части с 0.82 до 1.00 и даёт
  +0.016 R@1 / +0.017 MRR — на этом наборе эффект положительный, но в пределах
  одного вопроса, поэтому его нельзя рекомендовать без проверки на 300–500
  вопросах;
- `fixed` — контрольная группа; в продакшн-режиме используется `structure`.

### 6.2. Поиск по ППВС

`python -m rag.cli eval-ppvs`, 17 вопросов (`eval/ppvs_questions.jsonl`).
Метрика — попал ли нужный документ (дата + номер) в топ.

| метрика | значение |
|---|---|
| Recall@1 | 0.824 |
| Recall@5 | 1.000 |
| MRR@10 | 0.884 |

Промахи: ПДД (rank 3, конкурирующее постановление), УДО (rank 2), «статья 105»
(rank 5 — много постановлений упоминают ст. 105). Вопрос про назначение
наказания изначально был размечен на ППВС № 2 от 11.01.2007, но действующим
является № 58 от 22.12.2015 — разметка исправлена, после чего R@1 вырос
с 0.765 до 0.824.

### 6.3. Сравнение моделей

`python -m rag.cli bench`, один и тот же контекст, 6 вопросов,
`data/bench_results.json`:

| модель | файл | слоёв на GPU | среднее время | ток/с | цитат |
|---|---|---|---|---|---|
| YandexGPT-5-Lite-8B | 4.9 ГБ | все | 5.6 с | 31.1 | 1.5 |
| Saiga-YandexGPT-8B | 4.9 ГБ | все | 3.7 с | 26.9 | 1.7 |
| Saiga-Gemma3-12B | 7.3 ГБ | 20 (частично) | 35.7 с | 4.8 | 1.8 |

На RTX 4060 8 ГБ две 8B-модели грузятся целиком; 12B не влезает, поэтому
20 слоёв на GPU, остальные на CPU — отсюда падение до ~5 ток/с. Для основного
режима выбран YandexGPT-5-Lite: ответы полнее, скорость в этом замере выше,
чем у Saiga-8B. Saiga-12B имеет смысл только для эксперимента с качеством
на больших ответах, не для интерактива.

Замеры скорости зависят от прогрева и фоновой нагрузки: первый прогон дал
~19 ток/с у YandexGPT, второй — ~31 ток/с. Для диссертации нужно фиксировать
методику (один прогревочный прогон, затем 3 повтора, медиана).

Оценка качества ответов здесь качественная (полнота, корректность ссылок),
а не LLM-judge: нужен отдельный протокол слепой оценки юристом на 100+
вопросах.

## 7. Ограничения

- **УК РФ** — неофициальный источник, редакция 2025 г.; официальная сверка
  на дату обязательна для юридически значимых выводов.
- **ППВС** — 90 из ~120 уголовных постановлений 1997–2025; часть актов
  отсеяна фильтром (короткие, «О внесении изменений», утратившие силу).
  Полный список можно получить, ослабив фильтр в `rag/ppvs.py`.
- **PDF-артефакты ППВС**: конфликтные колонки и разрывы иногда переставляют
  слова внутри пункта (например, «К предмету вымогательства относится, в
  частности, чужое имущество» может перемешаться). Поиск и цитирование
  реквизитов от этого не страдают, но текст ответа требует выборочной сверки
  с `source_url`. Для чистовой версии нужен HTML/Бюллетень ВС РФ.
- **Оценка** — 62 вопроса УК + 17 ППВС; для статистической значимости
  сравнения чанкинга нужно 300–500 вопросов на акт.
- **Генерация** — ответы LLM не являются юридической консультацией; RAG
  снижает, но не устраняет галлюцинации. Проверка `_check_articles` ловит
  только ссылки на статьи, а не неверную интерпретацию.
- **Контекст 4096** — при 6 фрагментах и длинном ответе часть контекста
  отбрасывается; для длинных норм это ограничивает полноту.
