# RAG по уголовному праву РФ

Рабочая система: УК РФ + постановления Пленума ВС РФ → структурный чанкинг →
гибридный поиск (FAISS + BM25) → ответ локальной GGUF-моделью со ссылками
на статьи и пункты постановлений.

## Быстрый старт

```powershell
# 1. Зависимости (один раз)
.\.venv\Scripts\python.exe -m pip install -r requirements-rag.txt

# 2. Скачать и разобрать УК РФ (~522 статьи, 3–5 минут)
.\.venv\Scripts\python.exe -m rag.cli corpus

# 3. Скачать ППВС (датасет 35 МБ) и собрать корпус (~90 постановлений)
.\.venv\Scripts\python.exe -m rag.cli ppvs

# 4. Построить индекс (УК + ППВС, нужен GPU; ~1–2 минуты)
.\.venv\Scripts\python.exe -m rag.cli index --strategy structure

# 5. Спросить
.\.venv\Scripts\python.exe -m rag.cli ask "Что разъясняет Пленум о квалификации кражи?"
.\.venv\Scripts\python.exe -m rag.cli ask "Какое наказание за кражу с проникновением в жилище?"

# 6. Оценки
.\.venv\Scripts\python.exe -m rag.cli eval          # стратегии чанкинга УК
.\.venv\Scripts\python.exe -m rag.cli eval-ppvs    # поиск по ППВС
.\.venv\Scripts\python.exe -m rag.cli bench         # сравнение локальных моделей
```

Без генерации (только найденные нормы, быстро):

```powershell
.\.venv\Scripts\python.exe -m rag.cli search "кража с банковского счета" -k 5
.\.venv\Scripts\python.exe -m rag.cli ask "..." --no-llm
```

## Корпус

| Акт | Источник | Объём |
|---|---|---|
| УК РФ | `ukodeksrf.ru` (постатейно) | 522 статьи, 1 689 частей/примечаний |
| ППВС | датасет `Alexey5676/russian-supreme-court-plenum-acts` (CC0), собран с `vsrf.ru` | 90 постановлений 1997–2025, 2 475 пунктов |

Индекс: 842 чанка УК + 1 651 чанк ППВС = **2 493 чанка**, e5-base (768d).

ППВС режутся по пунктам, как УК по частям: заголовок чанка содержит дату,
номер и название постановления, поэтому цитата выглядит как
«п. 24 ППВС от 27.12.2002 № 29». В корпус не попадают акты «О внесении
изменений» и постановления, утратившие силу.

## Как это устроено

| Файл | Что делает |
|---|---|
| `rag/corpus.py` | качает оглавление и 522 статьи с ukodeksrf.ru, вырезает комментарии, парсит иерархию и части |
| `rag/ppvs.py` | скачивает датасет ППВС, чистит PDF-текст, выделяет пункты и реквизиты |
| `rag/chunking.py` | структурный чанкер УК + чанкер ППВС + naive-baseline |
| `rag/embeddings.py` | sentence-transformers, e5-base, префиксы query/passage |
| `rag/store.py` | FAISS IndexFlatIP + BM25, сохранение/загрузка |
| `rag/retriever.py` | RRF-гибрид, буст по «ст. N / ч. N» и по запросам о Пленуме |
| `rag/generate.py` | llama.cpp, системный промпт с обязательными цитатами |
| `rag/pipeline.py` | сборка всего, small-to-big раскрытие статьи |
| `rag/bench.py` | сравнение GGUF-моделей на одинаковом контексте |
| `rag/evaluate.py` | Recall@k, MRR, сравнение стратегий и ППВС |
| `rag/cli.py` | команды `corpus / ppvs / index / search / ask / eval / eval-ppvs / bench / stats` |

## Чанкинг: короткий ответ

Резать «по 512 токенов с перекрытием 20%» для кодекса — неправильно.
Правильно — **по структуре нормы**:

1. атомарная единица — **часть статьи** (подпункты «а)…г)» остаются с ней);
2. в каждый чанк добавляется **заголовок-путь**: `УК РФ → раздел → глава →
   статья → часть` — он же становится цитатой;
3. границы статьи не пересекаются;
4. примечания — отдельные чанки (в них определения «крупный размер» и т.п.);
5. перекрытие — 1 часть на стыке чанков внутри статьи и 15% предложений,
   если часть длиннее лимита; между статьями перекрытия нет.

Ограничение по токенам — 480 при лимите модели 512: 30–50 токенов уходит на
заголовок. Проверка — `python -m rag.cli eval` (см. `data/eval_results.json`).

### Что показал замер (62 вопроса, `eval/questions.jsonl`)

| стратегия | чанков | p50 токенов | Recall@1 | Recall@5 | MRR@10 | точность части |
|---|---|---|---|---|---|---|
| `structure` (overlap 1) | 842 | 296 | 0.903 | 0.984 | 0.940 | **1.00** |
| `structure-nooverlap` | 842 | 275 | 0.887 | 0.968 | 0.923 | 0.82 |
| `fixed` (окно 384) | 807 | 361 | 0.903 | 1.000 | 0.949 | 0.00 |

Выводы:

- на уровне «нашлась ли нужная статья» обе стратегии упираются в потолок
  (R@5 ≈ 1.0): для 62 вопросов разница в 1–2 вопроса находится в пределах шума;
- на уровне «та ли это часть статьи» структурный чанкинг даёт 100%, а
  скользящее окно не может ответить на этот вопрос вообще — в его чанках нет
  метаданных о части;
- перекрытие в 1 часть поднимает точность части с 0.82 до 1.00 и даёт
  +0.016 Recall@1 / +0.017 MRR (один вопрос), то есть на этом наборе эффект
  положительный, но его надо перепроверить на 300–500 вопросах;
- фиксированное окно выигрывает по MRR за счёт того, что его чанк — почти
  вся статья: для вопросов «какая статья» это удобно, для цитирования
  конкретной части — нет.

Именно поэтому в продакшн-режиме используется `structure`, а `fixed`
оставлен как контрольная группа эксперимента, а не как альтернатива.

### Поиск по ППВС

17 вопросов «какое постановление разъясняет…» (`python -m rag.cli eval-ppvs`):

| метрика | значение |
|---|---|
| Recall@1 | 0.824 |
| Recall@5 | 1.000 |
| MRR@10 | 0.884 |

Ошибки — в основном там, где несколько постановлений пересекаются по теме
(например, назначение наказания) или формулировка вопроса не совпадает
с названием постановления.

### Сравнение моделей

Один и тот же контекст, 6 вопросов, `python -m rag.cli bench`:

| модель | слоёв на GPU | среднее время | токенов/с | цитат в ответе |
|---|---|---|---|---|
| YandexGPT-5-Lite-8B | все (-1) | 5.6 с | 31.1 | 1.5 |
| Saiga-YandexGPT-8B | все (-1) | 3.7 с | 26.9 | 1.7 |
| Saiga-Gemma3-12B | 20 (частично) | 35.7 с | 4.8 | 1.8 |

8B-модели целиком влезают в 8 ГБ и дают ~27–31 ток/с; 12B приходится грузить
частично, поэтому она в 6–10 раз медленнее. Ответы всех трёх моделей
опираются на найденные нормы, но 8B-модели чаще обрывают ответ раньше
(меньше токенов), а 12B даёт более развёрнутые формулировки.

## Настройки

Переменные окружения:

```powershell
$env:RAG_EMBEDDING_MODEL = "intfloat/multilingual-e5-large"  # или deepvk/USER-bge-m3
$env:RAG_LLM_MODEL = ".\saiga_gemma3_12b-q4_k_m.gguf"
$env:RAG_LLM_CTX = "4096"
$env:RAG_DEVICE = "cuda"   # или cpu
```

Индекс и корпус по умолчанию лежат в `data/` (в git не попадают).

## Официальный доступ и ограничения

- **УК РФ**: текст собран с неофициального `ukodeksrf.ru` (редакция 2025 г.).
  Официальный источник — `pravo.gov.ru`, но он отдаёт акты целиком и плохо
  подходит для постатейного парсинга; для юридически значимых задач нужно
  сверять редакцию на дату.
- **ППВС**: официальный раздел `vsrf.ru/documents`, откуда и собран датасет
  (CC0). У каждого чанка сохранён `source_url` — текст можно сверить с
  оригиналом на vsrf.ru. Для публикации результатов зафиксируйте дату снимка.
- `pravo.gov.ru` доступен по HTTP и публикует официальные тексты НПА, но
  консолидированных редакций «одним файлом» там нет; для ППВС он не нужен —
  они публикуются в разделе документов ВС РФ и «Бюллетене ВС РФ».
- Ответы модели — не юридическая консультация; RAG снижает, но не устраняет
  галлюцинации, поэтому в ответе есть проверка ссылок на статьи.
